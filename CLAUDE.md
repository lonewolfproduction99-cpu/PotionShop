# Potion Shop: notes for Claude sessions

A cozy 3D potion shop management game (portrait, mobile first) made with GDevelop 5. Work happens on the branch `claude/potion-shop-gdevelop-766frn` (also the default branch). Read `README.md` for the full feature list.

## How the project is built

- `game/PotionShop.json` is **generated** by `python3 tools/build_project.py`.
  - The game logic is in `src/*.js` (Shop scene) and `src/garden/00_garden.js` (Garden scene). Each file becomes a JavaScript event.
  - Game data (recipes, herbs, upgrades, balance) is defined in `tools/build_project.py`.
- Assets are generated by code:
  - `tools/build_models.py`: 3D models (`.glb`) with a manifest of their sizes;
  - `tools/build_ui.py`: icons;
  - `tools/build_sfx.py`: sounds.
  - Models listed in `art/blender/edited.json` were edited by hand and are not regenerated.
- HTML5 export: `tools/export.sh <GDevelop portable app dir> docs`. It also applies the PWA layer (`tools/pwa/apply_pwa.py`; the docs build uses simulated test ads).
- Playgama upload zip: `python3 tools/platforms/build_playgama.py`, which writes `releases/potion-shop-playgama.zip`.
- Tests (headless Playwright): `node tools/test/play.js <build dir> <out dir> <scenario>`.
  - Scenarios: smoke, loop, queue, saveload, m2–m6, tutorial, pwa, prodads, playgama, bot.

## Editing models in Blender (current task)

The owner wants to reshape the shop owner, the waiting tables and the cauldron in Blender.

- The kit is in `art/blender/` (step-by-step guide: `art/blender/README.md`). It is also zipped as `releases/potion-shop-blender-kit.zip`.
- `art/blender/import_into_current_scene.py` imports these models into the open Blender scene, one collection each:
  - `char_owner` (7 animations: Idle, Walk, Work, Sit, Cheer, Angry, Carry);
  - `table_set` and `table_group_2` to `table_group_5`;
  - `cauldron`, `liquid`, `held_bottle` and `counter`.
- `art/blender/export_for_game.py` exports the selected asset to `art/blender/exported/<name>.glb`. It undoes the X offset that the import script added for display.
- `python3 tools/blender/update_models.py` (default input `art/blender/exported/`):
  - validates the files;
  - copies them to `game/assets/models/`;
  - re-measures their sizes into `manifest.json` and adds them to `art/blender/edited.json`;
  - rebuilds the project.

  Then re-export with `tools/export.sh` and rebuild the Playgama zip.

### Rules that keep edited models working

- **Scale and position:** 1 Blender unit = 1 game pixel (the owner is about 92 tall). Keep each model at the origin, standing on Z = 0 and facing the same way.
- **Axes:** in Blender, the table's chair is on the +Y side. In the GLB, game (x, y, z-up) maps to glTF (x, z, y).
- **Characters:** the animations move whole parts: `root` > `body` > legL, legR, torso > armL, armR, head. Keep those parts and names, and parent any new pieces to a part.
- **Liquids:** keep the material named `unlit`. The game tints it per potion and also accepts Blender's `unlit.001`-style names.
- **Tested so far:** with Blender 5.2 (bpy), all ten models imported and exported back with the same size, animations, unlit material and vertex colours. A game build using those exported files loaded and the owner's Carry animation played.
- **Open issues:** in the m5 test, the liquid check looks for the exact material name `unlit`, and the potion-stock check counted 2 instead of 1 (probably timing). Both looked test-related and are unresolved.
